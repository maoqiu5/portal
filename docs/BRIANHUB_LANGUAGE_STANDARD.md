# BrianHub 统一双语规则

## 1. 目标

BrianHub 门户和业务项目统一支持中文与英文。门户保存用户语言偏好，项目在首次加载时跟随门户；每个项目保留本地语言切换按钮，供用户即时调整。

## 2. 支持语言与回退

- 支持 `zh-CN`：中文。
- 支持 `en-US`：英文。
- 未提供、格式错误或不认识的语言值，一律回退 `en-US`。

## 3. 语言来源优先级

业务项目在处理页面或 API 请求时按以下顺序确定语言：

1. 网关转发的 `X-BrianHub-Locale` 请求头。
2. 浏览器 Cookie：`brianhub_locale`。
3. 默认 `en-US`。

门户 `/auth/check` 在认证成功后返回：

```text
X-BrianHub-User: <当前用户名>
X-BrianHub-Locale: zh-CN 或 en-US
```

网关必须把 `X-BrianHub-Locale` 转发给业务项目。

## 4. 门户职责

- 登录页和登录后页面提供中文 / English 切换按钮。
- 切换后设置 `brianhub_locale` Cookie。
- 已登录用户的选择同时保存到门户用户配置。
- 未登录访问时使用 Cookie；没有 Cookie 时默认英文。

## 5. 项目职责

- 每个项目页面保留中文 / English 切换按钮。
- 项目内切换后立即刷新当前 UI，并写入 `brianhub_locale` Cookie。
- 页面首次加载优先跟随门户传入语言。
- 不再新增独立用户级语言配置存储；语言偏好统一由 Cookie 和门户用户配置协调。

## 6. 翻译范围

必须双语化：

- 菜单、标题、按钮、表单、校验提示、弹窗、错误提示、空状态、筛选项、表格列名。
- 日期、数字、金额、百分比等显示格式。

默认不自动翻译：

- 业务原始数据。
- 用户输入。
- 邮件正文和附件内容。
- AI 原始输出。
- Markdown 文档正文。

这些内容如需翻译，应提供明确的单独功能，不与 UI 语言切换混用。

## 7. 实现要求

- 文案使用稳定 i18n key，不能把中文或英文硬编码散落在页面组件中。
- 至少维护 `zh-CN` 和 `en-US` 两套文案。
- 语言回退必须有自动化测试。
- 核心页面必须测试中文、英文两种模式。
- 更新项目的 `docs/README.md`、`docs/PRD.md`、`docs/CHANGELOG.md`，记录语言接入方式和验证结果。

## 8. 安全与边界

- 语言 Cookie 不承载身份、权限、密钥或业务敏感信息。
- 切换语言不能绕过门户登录、模块权限或网关鉴权。
- 不在前端暴露门户内部令牌、AI Key 或真实环境变量。
