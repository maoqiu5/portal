# 文档中心聚焦阅读设计

## 背景

BrianHub 项目数量增加后，文档中心当前“所有项目全部展开”的列表会让页面显得很重。用户需要更快找到常用文档，而不是一进入页面就看到每个项目的全部专题文档。

## 目标

- 默认突出项目总览和常用入口。
- 当前项目展开，其他项目折叠为摘要。
- 每个项目内优先显示标准文档：`README`、`PRD`、`DEPLOYMENT`、`CHANGELOG`。
- 专题文档收进“更多文档”，需要时再展开。
- 保留搜索、分类筛选、文档审计状态和右侧正文阅读。

## 设计

文档中心顶部新增“快速入口”区，链接到门户项目里的关键规则文档：项目总览、新项目接入、通用开发规则、网关/SSO/AI 规则和文档审计说明。

左侧索引改成项目折叠列表。没有选中文档时默认展开第一个项目；有选中文档时只展开该项目。项目标题仍显示审计状态和文档数量。

项目内部把标准文档放在“核心文档”小节，专题文档放进原生 `<details>` 折叠区。这样保留所有文档入口，同时降低默认视觉密度。

搜索或分类筛选时，前端自动展开有命中文档的项目，避免用户搜到内容但看不到结果。

## 验证

- 服务端页面测试应确认文档中心包含快速入口、项目折叠结构、核心文档和更多文档。
- 保留已选文档 Markdown 渲染行为。
- 运行 `npm test`。
